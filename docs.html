Simple Snapchat calls.

For Android 12.08.0.29. Log in, sync friends, get Quick Adds, send a message or snap, and post to My Story. The library fills the requests and uses the RUSOCIAL signer.

Get started

Install Python 3.10 or newer. Extract the ZIP, open a terminal inside its folder, and run:

python -m pip install --upgrade .
python examples/basic.py

The example asks for your RUSOCIAL API key and Snapchat login. Passwords are hidden while you type. It lists friends; it does not send or add anyone automatically.

import getpass
from rusocial_snapchat import SnapchatClient

with SnapchatClient(getpass.getpass("RUSOCIAL API key: "),
                    session_file="my-session.json") as snap:
    if not snap.is_logged_in:
        snap.login(input("Snapchat username: "),
                   getpass.getpass("Snapchat password: "))
    for friend in snap.sync_friends():
        print(friend.username, friend.display_name)

Keep my-session.json private. It contains login tokens and local key material so you can reopen the session. Passwords and the RUSOCIAL API key are not saved. Delete the file to start with a new device profile, or use logout() to end the session.

If Snapchat asks for a verification code

from rusocial_snapchat import LoginChallenge

try:
    snap.login(username, password)
except LoginChallenge as challenge:
    if challenge.kind != "two_factor_verification":
        raise
    method = "authenticator" if "authenticator" in challenge.methods else "sms"
    snap.verify_login(input("Verification code: "), method=method)

Other challenges are returned as errors for you to handle in Snapchat. The library does not bypass them.

Sync friends and Quick Adds

friends = snap.sync_friends()       # Saves and reuses sync tokens
friends = snap.sync_friends(full=True)  # Fetch a fresh full list
friends = snap.friends()            # Also refreshes the list

for suggestion in snap.quick_adds():
    print(suggestion.username, suggestion.display_name, suggestion.reason)

results = snap.search_users("friend_username")
snap.add_friend("friend_username")
snap.remove_friend("friend_username")
snap.block_friend("friend_username")
snap.unblock_friend("friend_username")
snap.mute_friend("friend_username")
snap.unmute_friend("friend_username")

Sync merges partial changes, username changes and removals into the saved list. Quick Adds fetches suggestions without adding anyone or marking suggestions seen. Friend actions also accept a Friend or QuickAdd object. Mute and unmute control that friend's story.

Send a message, a snap, or a story

sent = snap.send_message("friend_username", "Hello!")
sent = snap.send_snap("friend_username", "photo.jpg", duration=5)
sent = snap.send_snap("friend_username", "clip.mp4")
sent = snap.post_story("photo.jpg", duration=10)
print(sent.message_id, sent.request_id)

Messages and snaps use an existing one-to-one chat with a synced friend. If no chat is found, open one with that friend in Snapchat first. Groups, new-conversation creation, captions, stickers and mentions are not included.

Photos can be JPEG or PNG; duration is 1–10 seconds. Videos must be MP4 with one H.264 video track and optional AAC audio, at most 60 seconds. The video duration is read from the file. This library limits each file to 32 MiB and 8192 pixels per dimension. My Story uses your account's existing visibility settings.

These methods use the app's stateless send format over TLS. Media files are encrypted with a fresh AES key and IV, carried in the message metadata. The library does not implement the app's Fidelius/EEL end-to-end message encryption. It never reports success just because an upload finished: the send response must confirm the destination. Sends are not retried automatically.

snap.me gives the current account and snap.is_logged_in tells you whether one is saved. snap.save_session("my-session.json") enables saving an existing client. Use the client in a with block, or call close() afterward. A saved login may expire; is_logged_in does not contact Snapchat.

Client options

SnapchatClient(api_key, session_file=None, country_code="US", timeout=30) covers normal use. The country code is the two-letter country used for media upload routing. Device/session overrides and transport injection remain available for tests and existing profiles; no request payload is needed.

Read a failure

from rusocial_snapchat import AuthenticationError, SendError, SnapchatError

try:
    snap.send_message("friend_username", "Hello!")
except SendError as error:
    print(error, error.code, error.request_id)
except AuthenticationError as error:
    print(error, error.status, error.code)
except SnapchatError as error:
    print(error)

Password-login status 14 means invalid password for that username or email. Status 12 means account not found or password incorrect; status 13 means account not found. Those are login response statuses, separate from gRPC errors such as INVALID_ARGUMENT. Unknown statuses stay visible instead of being guessed.

A connection can fail after Snapchat receives a send. Check Snapchat before trying again to avoid a duplicate. Uploads that finish before a send is rejected may remain on Snapchat's storage.

Focused release

This release keeps the 16 action methods above and the 11 routes they need. The old general endpoint catalog, generated service classes, raw request interface and unrelated examples have been removed. Older scripts using snap.api, snap.services, snap.request() or generic builders must switch to the calls above.

The token route refreshes login credentials. QueryConversations resolves friend chats, and getUploadLocations prepares media storage. The signer handles the supported routes; unsigned legacy friend-list and user-search calls keep their app transport behavior. Registration and Web paths remain blocked.
